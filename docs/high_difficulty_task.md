# 課題：目的と装置の制限から、2室の換気制御を設計する

現在の課題ID：`ventilation-goals-v3`。数値による達成基準を示し、それを実現する条件と優先順位を学習者が設計する課題です。

## 学習者へ提示する問題

大学の自習室AとBでは、1台の換気装置を共有しています。
人の有無とCO₂濃度を読み取り、装置の制限を守りながら、次の目的を実現する制御プログラムを作成してください。
換気を始める・終える条件、どちらの部屋を優先するかは自分で決め、その理由を説明してください。

### 目的

- 人がいて1,000ppm以上の状態が続く各室の、連続未対応時間を**4ステップ以内**にする。
- 無人の部屋、または800ppm以下の部屋への運転を**0回**にする。
- 以下の装置の制限への違反を**0回**にする。

各シナリオを最後まで実行し、すべての基準を確認してください。
未対応時間は学習者の要求とは独立した参考待ち時間で計測します。
換気・退室・1,000ppm未満・点検で0に戻り、装置の停止制限による時間も含めます。

### 達成後の改善目標

数値基準を満たしたうえで、1,500ppm以上の有人室が換気を受けなかった延べ部屋ステップ数を、修正前より減らしてください。
両室が未対応なら、そのステップは2部屋ステップと数えます。点検中は除外します。
同じ入力列・同じ実行ステップ数で比較し、修正の理由を説明してください。
修正前が0なら0を維持し、改善の余地がないことを説明してください。

### 装置の制限

- 装置の動作は「A室を換気」「B室を換気」「停止」。同時換気はできない。
- 2ステップ連続で運転した次は、1ステップ停止が必要。
- 別室へ切り替える間には、1ステップ停止が必要。連続運転後の停止を兼ねられる。
- 点検中は必ず停止する。

### 使える情報と濃度の目安

各室の人の有無とCO₂濃度、点検モードを観測できる。
前回の装置動作、連続運転数、部屋ごとの要求待ち時間なども使える。
800ppm以下は不要な運転の対象、有人かつ1,000ppm以上は未対応時間の計測対象、1,500ppm以上は改善指標の対象とする。
これらは結果を測る基準であり、開始・終了条件や部屋の選択順を指定する規則ではない。
801〜999ppmへの運転は、この達成基準では禁止しない。

### 学習者が設計する部分

- どんな場合に換気要求をONにし、どんな場合にOFFにするか。
- 境目付近で濃度が上下したとき、前回の要求を保持するか。
- 両室が候補になった場合、濃度・待ち時間・継続などの何を優先するか。
- 条件が同時に成立した場合や、数値が同じ場合の扱い。
- 上記の判断を装置の制限とどう組み合わせるか。

「高濃度→待ち時間→継続」のような唯一の優先順は指定しない。
状態の保持は利用可能な方法であり、使うこと自体を正解条件にはしない。

## 実行と検討

個人思考→ペア対話→実行確認→全体対話の4フェーズで、予想・実行・理由の説明・修正を行う。
実行前に次の動作を予想し、実際に使われたルール、装置動作、内部状態を確認する。

評価は1つの出力列への一致ではなく、数値基準の達成状況と以下の指標を表示する。

| 観点 | システムが観測するもの |
|---|---|
| 装置の制限 | 点検中の運転、連続運転上限、停止を挟まない切り替え |
| 濃度への対応 | 有人かつ1,000以上の部屋への有効な換気、未対応の延べ部屋ステップ |
| 高い濃度への対応 | 有人かつ1,500以上で換気を受けなかった延べ部屋ステップ |
| 待たせ続けない | 部屋ごとの参考待ち時間の最大値 |
| 必要のない運転 | 無人室、または800ppm以下への運転回数（重複計上しない） |
| 判断の根拠 | 予想の理由、対話、変更前後のプログラム、修正理由の記録 |

一方を換気すれば他方が待つ場合や、停止の制限を守るために待つ場合もある。
必要な停止時間も含めて未対応4以内か確認する。800以下への運転は未達、801〜999への運転は観測指標として別に検討する。
制約違反の命令は換気への対応として加点しないが、実行は自動補正せず表示する。
制約違反がないことと、3つの数値基準すべてを満たすことは別である。
表示する達成状況は現在の実行範囲だけの確認であり、他のシナリオや将来のすべての入力での達成を意味しない。
途中でプログラムを変更すると修正前のプログラムと入力列を保持し、同じ入力・同じ長さで再実行したときに改善指標を比較する。

### 2種類の待ち時間

学習者の「要求待ち時間」は、本人が要求ONにした部屋で換気を受けなければ増える。
要求OFF、換気、点検で0に戻る。条件として参照できるのはこちら。

評価用の「参考待ち時間」は、本人の要求とは独立に、有人かつ1,000以上で有効な換気を受けなければ増える。
換気、無人、1,000未満、点検で0に戻る。要求をOFFにするだけでは消えない。
点検のステップは換気への対応機会から除外し、停止制限による時間は未対応にも含める。

### シミュレーションの範囲

1ステップは1分。CO₂濃度は入力列で与え、換気による濃度変化の物理計算は行わない。
この試作は装置の割り当てを比較するもので、実際の濃度低下、健康効果、消費電力は判定しない。

ルール編集は要求更新→候補選択→装置命令の3段階で支援する。
ルールの実行方法は教材操作として説明するが、条件と優先方針は完成例として指定しない。

## AIとの対話

- Aグループ：濃度の高い部屋への対応を重視。
- Bグループ：長く待った部屋への対応を重視。
- Cグループ：運転の継続と前回の要求の保持を重視。

各案は装置の制限を守る比較例だが、待ち時間などの数値基準を満たすとは限らない。未達を確認して修正を考える材料とする。
対話では、案が重視した目的、どんな状況で有利・不利か、どの入力で確かめるかを尋ねる。
実行結果と指標はシステムが計算し、AIは未確認の原因や唯一の正解を断定しない。
